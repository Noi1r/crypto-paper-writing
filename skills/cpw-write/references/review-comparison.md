# Paragraph comparison booklets

Use this optional collaboration mode when an author wants to review a batch of
proposed manuscript revisions later. A booklet pairs the original and proposed
passages with stable identifiers and reasons, so the author can discuss or select
changes individually.

When starting from research notes without an existing manuscript passage, use
the [first-draft discussion mode](drafting-from-materials.md#a-first-draft-for-later-discussion).
Label the new prose as a draft. An actual draft can become the baseline for a
later comparison; source notes should not be presented as an original manuscript.

## When to offer it

Complete the requested review and present its main findings first. When several
actionable paragraph or section revisions would benefit from direct comparison,
offer a booklet, especially for asynchronous review or substantial changes in
organization. For example:

> 要不要把这些建议做成逐段对照册？每项用 C1、C2 等编号，列出灰色原文、
> 红色建议和修改理由，方便你之后逐项讨论或选择。原稿保持不变。

If the author agrees, create the booklet. If the request already includes a
comparison booklet or equivalent artifact, proceed within that authorization.
Do not repeat the question after an answer or interrupt active paragraph-by-
paragraph collaboration with it. A single small wording change usually belongs
in the conversation. A review alone does not require creating a booklet.

The booklet presents candidates for discussion. Author interest in this format
does not establish acceptance of any particular revision or authorize applying
it to the manuscript.

## What each item contains

Choose the number of items and pages from the useful proposals. Do not impose
the counts or layout of a prior example.

| Field | Content |
|---|---|
| Identifier and title | Stable IDs such as C1, C2 and a short descriptive title |
| Location | Section, heading and paragraph anchor; add source lines or PDF pages when useful, naming which version they refer to |
| Issue and purpose | The concrete reading problem or technical concern; distinguish an established error, an open concern, a structural option and a style preference |
| Original | The exact passage from the identified baseline, with enough surrounding context to assess its role |
| Proposed | A complete candidate replacement, or an explicit description of a deletion or relocation |
| Reason and tradeoff | What changes, why it helps, what information or emphasis is affected, and any material unresolved condition |
| Decision | Initially pending; later record accepted, rejected or needs revision according to the author's feedback |

Use the manuscript's language for the passages and the author's preferred
language for explanations unless instructed otherwise. Preserve mathematical
notation, references, caveats and paragraph boundaries in the original. If an
excerpt is necessary, mark its boundaries explicitly.

Explain a substantial shortening or merger by identifying the actual redundancy
and the functions of the affected passages. Preserve useful background,
motivation, explanatory links and author structure. Fewer words or fewer pages
alone do not justify the change. Offer a larger structural alternative as such,
with its tradeoff visible, rather than presenting it as routine language polish.

A candidate may repair a demonstrated technical error, but that correction and
its support must be explicit. Leave unsupported results or missing data open;
do not manufacture them to complete the proposed passage.

## Prepare a separate review copy

Identify the manuscript version used for the comparison. Preserve the original
sources and work in a separate output or preview directory. Save the relevant
baseline passages and source revision, hashes or other reliable version markers
so a later accepted change can be checked against its original context.

For a PDF, use readable gray for original text and red for proposed text, with
explicit "Original" and "Proposed" labels. Color communicates comparison status;
it does not establish which wording is correct or approved. Keep rationale text
visually distinct. Stack long passages when columns would make text or formulas
too narrow. Let blocks flow over pages, keeping the item ID visible on continuation
pages. Add a short index when it helps navigate a longer booklet.

For a deletion, show the original and state what is proposed for removal. For a
move, identify the old and new locations, and distinguish unchanged relocated
text from rewritten text. Keep equations, tables, footnotes and citations legible.
Cross-references must identify the baseline or proposed version they point to.

Use the available document/PDF workflow for rendering and inspection. Keep an
editable source; a small change map can connect IDs, locations, passages, reasons
and decisions when useful. A complete manuscript with changes in red is an
additional option when the author wants to assess the overall flow; it is not
required for every booklet. If PDF production is unavailable, offer a readable
comparison in another available format and describe that limitation.

Keep real manuscript extracts and review artifacts in the paper project.
Reusable toolkit examples and templates contain only synthetic or public content.

## Discuss and adopt by identifier

Let the author refer to an item by its ID, for example "reject C1" or "revise C3
while keeping both paragraphs." Keep IDs stable across discussion; append new IDs
for new proposals instead of silently renumbering existing ones. Make revised
candidates and changed decisions identifiable. Do not mark approval on the
author's behalf.

Apply selected revisions only when source edits are authorized in the current
collaboration. Approval to produce a preview leaves the manuscript unchanged.
Before applying a selected item, compare the current passage with its recorded
baseline. Reconcile intervening edits and ask a focused question only if the
author's intended change is now unclear. Preserve rejected and unresolved choices.

## Check the delivered comparison

- Match original passages to the stated baseline and inspect the candidate for
  unintended changes in claim strength, assumptions, notation, numbers or citations.
- Check item IDs, locations, version labels, colors and any decision records.
- For a PDF, inspect rendered pages for clipping, awkward breaks, missing glyphs
  and unreadable mathematics; resolve references where feasible and disclose any
  remaining issue. Use the artifact workflow's validation requirements.
- Confirm that preview generation did not edit the original manuscript. Report
  only the checks performed; a successful build establishes no proof or result.

Deliver the booklet with a short explanation of how to discuss or select its
items. Continue the review from the author's choices rather than treating the
booklet as an automatically accepted rewrite.
