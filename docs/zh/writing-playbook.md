# 密码学论文写作指南

统一入口：`skills/cpw-write/SKILL.md`；各节指南在其 `references/sections/` 中，
协作润色、语言表达和参考论文阅读指南也在 `references/` 中，按当前任务读取。
示例均为合成材料。具体论文的草稿、结果和风格记录保存在论文项目里。

## 核心原则

先理解论文实际解决的问题、采用的方法和已经建立的结果，再选择表达结构。
摘要应讲清问题、方法和主要结果；技术概览应解释实际困难与关键观察。
段落、贡献、问题、insight 和图的数量由内容决定。

修改已有稿件时，保留清楚的作者结构和术语。根据请求范围开展工作：全文规划
先给目录草案，局部润色先读相关上下文。每段承担明确的解释任务，调整结构时
说明它解决了什么理解困难。

主张的假设、量词、安全模型、比较条件和证据状态应保持准确。贡献可以引用
定理、算法或表格；必要的限制条件应当与主张一起出现。数值来自项目记录，
引用有可核对的来源。实验归因和组件作用以实际证据为准。

## 全文参考结构

| 部分 | 主要职责 | 调整依据 |
|---|---|---|
| Abstract | 问题、方法和主要结果 | 根据内容与会场要求安排段落 |
| Introduction | 动机、问题、最相关前作和主要贡献 | 贡献可写成段落或列表 |
| Technical Overview | 技术困难、关键观察及其如何导向结果 | 可并入引言，也可独立或置于必要定义之后 |
| Preliminaries | 后文使用的记号、模型、定义和已有工具 | 较长的问题定义或模型可单独成节 |
| Main Technical Content | 协议、构造、算法或理论结果 | 按概念和论证的依赖关系拆分与排序 |
| Correctness / Security / Analysis | 所声明性质及其支持、相关代价 | 可紧跟构造，也可独立成节 |
| Evaluation | 参数计算、成本分析或测量对研究问题的回答 | 根据实际结果选择指标与比较 |
| Related Work | 与相关成果的具体关系和比较条件 | 可前可后；引言中仍交代最直接的关系 |
| Conclusion | 结果的含义、主要取舍或剩余问题 | 会场允许且没有额外总结价值时可省略 |
| References / Appendix | 引用与详细支撑材料 | 按论文需要及会场要求安排 |

为每一节说明它要解决的阅读问题、使用的现有材料和前后依赖。篇幅优先支持
主要贡献的理解和评估，根据实际投稿要求分配。Related Work 放前面可以先建立
问题背景；放后面可以利用已经介绍的技术细节进行比较。

## 各节检查什么

- **标题与摘要**：准确标识问题和结果，保留理解结论所需的范围条件。
- **引言与贡献**：研究问题和具体推进清楚，贡献之间没有人为拆分或重复。
- **技术概览**：困难、关键观察和结果之间有清楚的联系，直觉与正文相符。
- **预备知识**：提供后续需要的定义和工具，解释必要的新记号。
- **主要内容**：对象、输入输出、协议步骤或定理陈述明确，论证有适用条件。
- **安全性与正确性**：区分形式保证、具体估计和实验检查，清楚标明证明状态。
- **实验**：测量边界、比较口径和数据来源明确，结论与归因不超出证据。
- **相关工作**：技术转述有一手来源，改进、互补和不同条件被准确表达。
- **结论与附录**：结论提供有用的综合；附录与正文支撑关系清楚，符合会场政策。

## 新论文的写作参考与风格

默认流程是：先明确本论文的问题和已有结果，再阅读适合的相关论文，形成
当前论文的写作方案。具体方法见
`skills/cpw-write/references/writing-from-related-work.md`。

1. **选择参考论文。** 最接近的技术工作有助于确定需要交代的背景、定义和比较；
   贡献类型相近、表达清楚的论文有助于选择组织方式和表达深度。两者可以来自
   同一篇论文，也可以来自不同论文，不规定篇数。
2. **阅读对应正文。** 分析内容覆盖、章节依赖、直觉与形式内容的衔接、段落
   推进和记号密度。记录相关章节及其写法为什么适合当前工作。仅凭摘要无法
   判断全文结构和语言风格；无法读取的内容应说明。
3. **形成写作方案。** 给出目录、每节职责、已有支撑材料和适用的表达选择。
   在 `STATE.md` 中简要记录，或链接项目已有笔记。参考论文中的技术结果和
   贡献不能自动成为本文内容；主张的强弱仍由自己的证据决定。
4. **结合改稿反馈调整。** 开始撰写时，可先写引言或技术概览等关键部分，根据
   作者反馈改进方案，再用于后续章节。

这套分析主要用于新稿启动或大幅重组。局部润色沿用已有方案和清楚的稿件习惯，
无需反复重新检索。作者明确偏好和会场要求继续适用。个人 `STYLE.md` 仅在作者
明确要求建立个人风格档案时使用，不是新稿写作的前置条件。实际论文和参考笔记
保存在论文项目中，工具箱只保留通用方法和合成示例。

## 语言自然、解释清楚

这些要求同时用于初稿和润色，具体示例见
`skills/cpw-write/references/field-language-and-clarity.md`。

- **技术术语符合当前子领域的用法。** 结合参考论文的语境和本稿定义选择词语。
  同一个对象保持同一个名称，例如 commitment、witness、verifier；不要为了
  避免重复而换成看似高级的近义词。真正的新概念可以命名，并明确给出定义。
- **普通叙述用常用词和具体动作。** 清楚说明谁计算、发送、检查或证明什么。
  清理没有实质内容的强调、抽象名词堆叠、生造标签和多余比喻。词语是否合适
  取决于语境；robustness、extraction 等可能有严格的技术含义，不宜机械禁用。
- **根据读者已有知识安排解释。** 默认让相邻子领域的密码学研究者能读懂引言
  和概览。必要时在定义或公式附近解释它的作用，或用小例子说明难点；技术正文
  可以使用前文已经建立的定义，无需反复补充基础知识。
- **把关键连接写出来。** 检查对象、动作、条件和指代是否清楚；两步之间需要
  理由时，给出已有材料支持的理由。连词不能代替论证，也不能为了顺畅而补出
  未经支持的因果关系。句子是否需要拆分取决于理解难度，不设固定词数。

完成初稿后，分别检查术语是否自然、解释是否有跳步，再核对技术含义、引用和
数字。通俗易懂的目标是降低理解负担，同时保留必要的术语、假设和精度。

## 协作润色中的具体判断

- 先处理段落作用、内容位置、缺失前提和重复，再调整句子与词语。
- 在读者理解用途时引入中间量、计数对象或优化步骤；先交代它回答的问题。
- 根据后文需要裁剪背景，保留影响算法、正确性、安全性和成本解释的条件。
- 把贡献写清为实际困难、处理机制和支持的结果，不停留在“更紧”“更高效”。
- 给公共定义和约定安排主要说明位置；重复表格也应检查是否提供独立信息。
- 标准定义引用标准，具体分析和实验结果引用其实际来源。
- 结果段解释主要观察，区分组件和整体，并确认收益归因符合所选配置和比较。

这些是按内容选择的判断原则。示例见
`skills/cpw-write/examples/revision-decisions.md`。
局部修改直接使用现有稿件和支持材料；缺少项目记录时无需先建立一套台账。
作者改变段落目标后，重新组织完整段落，并沿用已经接受的术语和判断。

## 相关流程

- 需要文献定位时，使用文献检索、阅读笔记和引用核验技能。
- 修改数值或表格时，核对原始来源；项目采用 `EVIDENCE.md` 时同步记录并运行
  适用的源文件审计。审计不能代替对实验、推导或宏与图片中数值的核对。
  详见 `docs/evidence-audit.md`。
- 需要模拟审稿、rebuttal 或投稿准备时，分别使用对应技能并报告实际检查范围。
- 对构建后的稿件按需要检查排版；构建成功不代表论证正确。
